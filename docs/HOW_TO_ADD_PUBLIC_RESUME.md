# Add the approved public résumé

The supplied private UNDP résumé is NOT public-approved and has not been copied into public assets. The current site intentionally shows an inactive “Résumé coming soon” state without requesting a PDF. The complete viewer is prepared and tested using an isolated in-memory fixture; no fake résumé ships.

1. Create a separate public-safe PDF. Remove private phone numbers, personal identifiers, private references and document metadata containing sensitive details. Inspect all pages visually and with text extraction; do not merely cover a phone with a white rectangle. A file in `public/` will be downloadable by anyone if this site is later published. Obtain the owner's explicit approval of the exact final document.
2. Copy only that approved file to `C:/projects/TrunalOS-portfolio/public/resume/Trunal_Patil_Resume_Public.pdf`. Do not copy the old private PDF as a shortcut.
3. In `src/content/resume.ts`, set `resumeManifest.approvedForPublic` to `true` after approval. The path is `resume/Trunal_Patil_Resume_Public.pdf`. Vite also checks actual file existence when starting/building; both conditions are required. Restart the dev server or rebuild after adding/removing the file. Approval alone cannot create a link to a missing file.
4. Run `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`. Preview locally, open Contact → View Résumé, check Close, Open in new tab and Download. Check file HTTP 200 and application/pdf, native preview readability, keyboard/Escape and return focus, desktop 1440×900 and 390×844 mobile. Phone browsers get a prominent Open in new tab/Download fallback. Desktop uses the local native object PDF renderer when navigator.pdfViewerEnabled and width permit it; if blank or unsupported, visible new-tab/download controls remain available.
5. Run isolated viewer tests with `node scripts/resume-fixture-build.mjs` then `node scripts/controlled-upgrade-browser.mjs` while production preview is running on 4173. The harness in `.local/resume-fixture-dist` imports the real component but is excluded from normal `dist/`. The PDF is generated in memory and fulfilled only by the test route. The current acceptance suite explicitly tests the missing public-PDF state; after approval, update that branch to assert View Résumé with the approved local file, retaining the separate `asset={null}` unit test. Update the output-audit's no-PDF delivery gate to permit only the approved path after manual privacy review, while preserving all phone/secret checks. The fixture must never be copied to public/.

Native PDF controls vary across browsers and platforms. A browser plugin may own focus while reading; visible Close and Open in new tab provide reliable exits. Test actual intended browsers and assistive technology; automated Chrome emulation does not certify hardware mobile or screen reader behavior. No third-party viewer, backend, SaaS or external runtime request is used. Adding a PDF does not authorize pushing or deploying.
