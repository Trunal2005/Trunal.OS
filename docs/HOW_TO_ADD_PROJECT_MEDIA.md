# Add genuine project evidence

1. Verify the exact owner repository and commit. A similarly named repository is not interchangeable. Search committed screenshots and safe existing local captures first; run a genuine keyless demo only in a disposable copy. Never publish a real résumé, customer records, contact details, secrets or payment instruments.
2. Place reviewed web assets under `public/project-media/<project-id>/`: a readable WebP preview, PNG fallback, small thumbnail and full original UI capture encoded as WebP. Preserve the original source privately when it carries risk. Crop/resize/compress only; never change UI labels, results, charts or features. Keep a complete original available when a preview uses a detail crop.
3. Add a typed record in `src/content/project-media.ts`, then assign it to the matching `Project.media` in `projects.ts`. Record actual dimensions, title, descriptive alt, honest caption, source/ref, verification date and context. `real-ui` means a real application capture; diagrams/concepts must keep their own kind and label. No remote URLs or visitor API requests.
4. Add source/hash/license/privacy decisions to `PROJECT_MEDIA_INVENTORY.md` and the provenance manifest. Do not infer a general redistribution license when a repository has no LICENSE. Local integration and public publication are separate decisions; publishing still needs owner authorization.
5. Preview captions must explain synthetic/simulation data and any limited capture scope. A form is not evidence of successful AI analysis. Never invent an outcome to make a case look complete.
6. Run typecheck, lint, unit tests, production build and `npm run test:browser`. Inspect actual desktop/phone gallery, thumbnail active state, native-modal keyboard focus, Escape/restoration, 100% zoom/panning, PNG fallback and failed-file state. Check image transfer sizes and layout shifts. An initial overview should not fetch project images or full-resolution files.

The local-only `scripts/prepare-project-media.py` documents this pass's image encoding and checks committed Git blob bytes. Its absolute source paths are research inputs, not build dependencies. All assets needed by `npm run build` are already in this repository. No new package, image service or account is needed.
