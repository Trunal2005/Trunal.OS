# Add professional experience

Add an `ExperienceRole` record to `roles` in `src/content/experience.ts`: stable ID, company, exact role, dates, context, responsibilities, a useful abstract pipeline, transferable skills and evidence references. The Experience Studio renders every visible role; no new building is necessary. Its physical stage controls retain Nitrix as the first role's featured pipeline.

Use actual résumé/owner facts and verify public links. Leave `approvedMetrics` and `approvedClients` empty until evidence and permission exist. Their contents are deliberately not automatically published: add authorized presentation only after review. Never infer client endorsement or draw a fake performance chart. Use original abstract visuals when media rights are unavailable.

Check dates, current-role status and professional titles before release. Roles remain separate from the About/Education chronology and project case studies. Run the checks and browser review described in `CONTENT_EDITING_GUIDE.md`.
